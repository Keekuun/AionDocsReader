Agent 原理 · 第 4 课

权限与确认：让人类保持控制权

agent 能写文件、能执行 shell——能力越大，闯祸越快。学完这课，你能说清确认机制的设计，并理解「自动批准」和「允许列表」各自的代价。

问题：循环里全是危险动作

第 2 课的工具清单里，Read 无害，但 Write 会覆盖文件，Edit 会改代码，ExecCommand 能执行任意 shell——包括 rm -rf。而第 1 课的循环是自动跑的：模型每个 turn 都可能发起新的危险调用，没有人类介入的话，一次幻觉就是一次事故。

核心原则：自主性（autonomy）和控制权（control）是一对矛盾。生产级 agent 不追求「全自动」，而是追求「可校准的自主」——危险动作默认要人批，被信任的动作才放行。

aionrs 的确认器（真实代码）

aion-agent 里的 ToolConfirmer 只有几十行，但把确认模型说全了：

pub fn check(tool_name, tool_input_display) -> ConfirmResult {
    // ① 全局自动批准开着 → 直接放行（YOLO 模式）
    // ② 工具在允许列表里   → 直接放行
    if auto_approve || allow_list.contains(tool_name) {
        return Approved;
    }
    // ③ 否则问人类：[y]es / [n]o / [a]lways / [q]uit
    //    选 a → 把这个工具加进允许列表，以后不再问
}
📄 真实代码：aion-agent/src/confirm.rs 第 36 行

四个选项的设计很讲究：y 批这一次，n 拒这一次，a 永久信任这个工具，q 终止整个 run。用户在「被打扰次数」和「控制风险」之间自己找平衡。

从引擎到界面：确认是一次跨进程往返

aionrs 是引擎，不直接弹窗。在完整产品里，确认请求要穿过几层到达人类：

模型发起 tool_use（比如 Write /exec rm 命令）
  → 引擎暂停这个 tool round
  → AionCore 产生一条 confirmation 记录，WebSocket 推给界面
  → AionUi 弹出确认框，人类点「允许 / 拒绝」
  → POST /api/conversations/:id/confirmations/:callId/confirm
  → 引擎收到结果，继续或放弃这个工具调用
📄 你在 AionCore 见过这条链路：crates/aionui-conversation/src/routes.rs 里的 confirmations 路由

关键设计：循环在等确认时是暂停的，工具结果只有获批后才产生。被拒绝的调用也会作为结果写回历史（「用户拒绝了」），模型据此换方案而不是硬闯。

深入一层：Plan 模式——把「不许写」做成双保险

确认机制是「问了再批」，plan 模式更彻底：进入后 agent 进入只读探索状态，先出实施方案，人类批准计划后才动手。它是怎么保证只读的？不是求模型自觉，而是两层：

// 第一层：工具集过滤——写类工具的名片根本不进请求
registry.to_tool_defs_filtered(|tool| 只允许 Read / Grep / Glob);

// 第二层：系统提示词明文禁令
"Plan mode is active. You MUST NOT make any edits, run any
 non-read-only tools, or otherwise make any changes to the system."
📄 真实代码：aion-agent/src/plan/ 目录（prompt.rs 第 16 行是禁令原文）；过滤在第 2 课见过的 to_tool_defs_filtered
设计原则：能力层 + 意图层双保险。只发只读工具的名片，模型没有能力写；提示词再声明意图，模型知道不该写。单靠任何一层都不可靠：只过滤名片，模型可能用 Read 的奇怪参数绕；只写提示词，模型可能幻觉出工具调用。你以后设计权限时记住这个句式：能力上做不到 + 意图上知道不该。

另外一个方向：skill（技能包）可以声明自己需要哪些工具的自动批准，加载时通过 add_to_allow_list 动态加进允许列表——权限不是全局开关，而是按场景精确授予。

动手任务（10 分钟）

在 AionUi 里触发一次真实确认

1. 启动 AionUi（bun run start，别忘了 unset ELECTRON_RUN_AS_NODE）。

2. 新建对话，发一条需要写文件的消息，比如「在当前目录创建一个 hello.txt，写上今天的日期」。

3. 观察弹出的确认框，先点一次「拒绝」，看 agent 怎么回应；再发一次，点「允许」。

✓ 完成标志：能说出拒绝之后 agent 的行为变化（它收到「被拒绝」的结果，换策略或解释原因），并在 AionCore 的 routes.rs 里找到处理你点击的那条路由（搜 confirmations）。
