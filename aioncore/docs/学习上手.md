# AionCore 学习上手（含 Rust 零基础）

这份文档假设你写过 JavaScript / TypeScript，但没写过 Rust。官方架构说明在仓库根目录的 [ARCHITECTURE.zh-CN.md](../ARCHITECTURE.zh-CN.md)，给 AI 助手的约束在 [AGENTS.md](../AGENTS.md)。这里用本仓库的真实代码，把「Rust 长什么样」和「请求在程序里怎么走」接到一起。

当前版本：workspace `0.2.2`（见根目录 `Cargo.toml` 的 `workspace.package.version`）。Rust 工具链锁在 `rust-toolchain.toml` 的 **1.95.0**。语言版本是 **edition 2024**。

## 1. 这个程序是干什么的

AionCore 编译成一个命令行程序，名字叫 `aioncore`。它是 AionUi 桌面应用的本地后端：

- 用 HTTP 提供 REST API（对话、文件、设置、定时任务……）
- 用 WebSocket 把 Agent 的流式输出推到界面
- 用 SQLite 存用户、对话、消息
- 拉起 Claude Code、Codex、内置 aionrs 等 Agent 子进程

AionUi 不会把 Rust 嵌进网页。它是另起一个进程，再通过本机端口访问。开发时 AionUi 会执行类似这样的命令（参数组装在 AionUi 的 `packages/web-host/src/backend-launcher.ts`）：

```text
aioncore --port <空闲端口> --data-dir <数据目录> --parent-pid <AionUi进程号> --local --log-level debug
```

你单独调试后端时可以自己跑。默认监听地址在 `crates/aionui-common/src/constants.rs`：

- 主机 `127.0.0.1`（`DEFAULT_HOST`）
- 端口 `25808`（`DEFAULT_PORT`）

被 AionUi 拉起时端口以 `--port` 为准，不一定是 25808。

## 2. 先把 Rust 工具装上，再编译

```bash
# 安装 rustup 后，本仓库会按 rust-toolchain.toml 使用 1.95.0
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source "$HOME/.cargo/env"

cd AionCore
cargo install --path crates/aionui-app --locked
export PATH="$HOME/.cargo/bin:$PATH"
aioncore --help
```

`--locked` 表示严格按 `Cargo.lock` 里的依赖版本编译，和 CI 一致。第一次编译会下载 crates.io 和 GitHub 上的 `aionrs`（tag `v0.2.11`），耗时很长，这是正常的。

日常命令：

| 命令 | 作用 |
| --- | --- |
| `cargo check --workspace` | 只做类型检查，比重编可执行文件快，改代码时先用它 |
| `cargo run --bin aioncore -- --help` | 编译并运行，适合不安装到 `~/.cargo/bin` 时试跑 |
| `cargo test --workspace` | 跑测试。仓库的 `just test` 用的是 `cargo nextest`，本机没装 nextest 时用这条 |
| `cargo fmt --all` | 格式化 |
| `cargo clippy --workspace` | 静态检查，警告在这个项目里常常当成错误 |
| `cargo install --path crates/aionui-app --locked --force` | 覆盖安装，给 AionUi 用 |

`just` 是可选的任务运行器（见根目录 `justfile`）。没有 `just` 时，直接用上面的 `cargo` 命令即可。

数据目录默认是当前目录下的 `data/`。和桌面应用一起用时，数据目录由 AionUi 传入，不要和你手工 `cargo run` 的 `data/` 搞混。同一个数据目录同时只能有一个 `aioncore`，第二个会报「another aioncore already owns this data directory」。

## 3. Rust 和 TypeScript 对照（只记这份仓库里真会出现的）

下面每一节都先给一句人话，再给本仓库里的原句。

### 3.1 文件、模块、crate

TypeScript 一个文件夹可以随便 `import`。Rust 一个「包」叫 **crate**。本仓库是一个 **Cargo workspace**：根 `Cargo.toml` 的 `members` 列出 27 个 crate，每个都在 `crates/<名字>/`。

- `lib.rs`：这个 crate 是库，给别的 crate 用。几乎每个领域 crate 都有。
- `main.rs`：这个 crate 是可执行程序。全仓库只有 `crates/aionui-app/src/main.rs`。编译产物名字在 `aionui-app/Cargo.toml` 里写成 `aioncore`。

`lib.rs` 顶部的 `mod xxx;` 表示「这个文件旁边有 `xxx.rs` 或 `xxx/mod.rs`，把它编进来」。不写 `mod`，那个文件就不属于本 crate。`pub use` 是对外重新导出，别的 crate 才能 `use` 到。

`crates/aionui-common/src/lib.rs` 开头就是这个模式：先 `mod error;`，再 `pub use error::ApiError;`。

crate 之间用包名加下划线引用：目录 `aionui-conversation`，代码里写 `aionui_conversation::`。

### 3.2 变量默认不能改

```rust
let cli = Cli::parse();
```

`let` 类似 `const`。要改值必须写 `let mut`。函数参数默认也不可变。看到 `mut env` 就是「这个环境配置后面还会被改」。

### 3.3 类型写在名字后面

```rust
pub port: u16,
pub data_dir: PathBuf,
pub parent_pid: Option<u32>,
```

`u16` 是 0～65535 的整数，用来放端口。`u32` 是进程号那种无符号整数。`PathBuf` 是可增长的路径，类似字符串形式的文件路径。`String` 是可拥有的文本；`&str` 是借用的文本切片，类似「只读地看一段别人的字符串」。

### 3.4 `Option`：可能没有

TypeScript 用 `number | undefined`。Rust 用 `Option<u32>`，要么 `Some(12345)`，要么 `None`。

`main.rs` 里 `cli.parent_pid` 就是 `Option`：AionUi 会传入，你手工启动时可以不传。

### 3.5 `Result`：可能失败

TypeScript 用 `try/catch`。Rust 把失败写进返回值：`Result<成功类型, 错误类型>`。

```rust
fn run_main() -> Result<ExitCode, MainError> {
```

成功是 `Ok(...)`，失败是 `Err(...)`。行尾的 `?` 表示「如果这里是 Err，立刻把错误返回给调用者」。`main.rs` 里大量 `.await?` 就是「等这个异步操作，失败就往上抛」。

没有异常穿透。你必须处理 `Result`，或者用 `?` 交回去。这是读 Rust 时最重要的习惯：先看函数签名的错误类型，再看函数体。

### 3.6 `struct` / `enum` / `impl`

`struct` 是字段捆在一起，类似 TypeScript 的 `type` 对象。

```rust
pub struct ConversationRouterState {
    pub service: ConversationService,
    pub task_manager: Arc<dyn IWorkerTaskManager>,
    pub active_leases: Arc<ActiveLeaseRegistry>,
}
```

`enum` 是「若干种里的一种」。`ApiError`（`crates/aionui-common/src/error.rs`）就是一个大枚举：`NotFound`、`Unauthorized`、`Internal`……每种可以带自己的数据。这比一个万能 `Error` 类更明确。

`impl` 是给某个类型写方法。`Command::as_str` 就是给 `Command` 枚举加方法。关联函数（第一个参数不是 `self`）用 `Type::function()` 调用，例如 `Cli::parse()`。方法用 `value.method()`。

### 3.7 `trait`：接口

`trait` 接近 TypeScript 的 `interface`。`crates/aionui-db/src/repository/conversation.rs`：

```rust
#[async_trait::async_trait]
pub trait IConversationRepository: Send + Sync {
    async fn get(&self, user_id: &str, id: &str) -> Result<Option<ConversationRow>, DbError>;
    async fn create(&self, row: &ConversationRow) -> Result<(), DbError>;
}
```

业务代码只依赖这个 trait，不依赖「SQLite 那一份具体实现」。具体实现在同目录的 `sqlite_conversation.rs`，类型名以 `Sqlite` 开头。这样测试可以换一个假的仓库。

`&self` 表示方法借用自己，不拿走所有权。`&mut self` 表示要修改自己。

### 3.8 `async` / `await` 和 Tokio

`.await` 和 TypeScript 一样，是「这里会停下来等 I/O」。差别是：Rust 的 async 函数必须跑在一个运行时上。本项目用 **Tokio**。

`main.rs` 里同步的 `fn main` 先建一个多线程 Tokio runtime，再 `block_on(async_main(...))`。所以真正的服务器逻辑全在 `async fn async_main`。

看到 `tokio::spawn(async move { ... })`，就是丢到后台跑，不挡住当前函数。路由组装时启动 WebSocket 转发、渠道插件恢复，都是这种写法（`crates/aionui-app/src/router/routes.rs`）。

### 3.9 所有权、借用、`Arc`

这是和 JS 差别最大的一点。JS 里对象谁都能拿着。Rust 里每个值有一个主人。把值传给函数，默认是把主人交出去（move）。对方用完你就不能再用。

只想让对方看一眼，传引用 `&T`。想让很多地方共享、而且会跨线程，用 `Arc<T>`（原子引用计数，类似「共享指针」）。要在共享的同时还能改内部，常见组合是 `Arc<Mutex<T>>`。

对话路由状态里的 `Arc<dyn IWorkerTaskManager>`：

- `Arc`：多处共享同一份任务管理器
- `dyn Trait`：运行时才知道具体类型，只要它实现了这个 trait

`Send + Sync` 写在 trait 后面，表示这个东西可以安全地丢给别的线程。Tokio 多线程运行时几乎处处要求它。

### 3.10 属性：函数上面的 `#[]`

`#[derive(Clone)]` 表示「请编译器自动实现克隆」。`Clone` 是显式 `.clone()`，不是偷偷拷贝。

`#[tokio::main]` 在别的项目很常见，本仓库的 `main` **没有**用它，而是手写 runtime，方便按不同子命令返回不同错误。

`#[async_trait::async_trait]` 是为了让 trait 方法可以是 `async`。Rust 原生的 trait 对象（`dyn Trait`）对 async 支持不完整，所以仓库用这个宏。

### 3.11 可见性

- 不写 `pub`：只有本模块能用
- `pub`：别的 crate 能用
- `pub(crate)`：只有本 crate 能用。`cli.rs` 里的 `Cli` 就是 `pub(crate)`，因为只有 `main.rs` 需要解析命令行

### 3.12 模式匹配

`match` 类似 TypeScript 的 `switch`，但必须覆盖所有分支。`main.rs` 的 `async_main` 用 `match cli.command` 把子命令分发出去：没有子命令就启动 HTTP 服务，有 `Doctor`、`User` 等就跑完就退出。

`if let Some(x) = option` 是「如果是 Some 就把里面的值拿出来」。

### 3.13 错误类型分层

不要在业务里到处丢 `ApiError`。项目约定：

- 领域内部用自己的错误，例如 `ConversationError`、`DbError`
- 到了 HTTP handler，再 `map_err(ApiError::from)` 转成接口错误

`conversation` 的 `routes.rs` 里有 `impl From<ConversationError> for ApiError`，这就是那一层转换。`From` 实现了之后，`?` 和 `.into()` 可以自动转。

### 3.14 宏

带 `!` 的是宏，不是函数：`println!`、`tracing::info!`、`vec!`、`sqlx::migrate!`。`tracing::info!(stage = "instance_guard.acquire", "...")` 是结构化日志：前面是字段，最后一句是消息。生产环境一般是 `info`，开发模式 AionUi 传 `--log-level debug`。

## 5. 一个领域 crate 里面怎么分文件

以 `aionui-conversation` 为样本。新功能请沿用这个形状，不要把 SQL 写进 handler。

| 文件 | 只做什么 |
| --- | --- |
| `lib.rs` | `mod` 声明和 `pub use`，不写业务 |
| `routes.rs` | 定义 URL，把 HTTP 转成对 service 的调用 |
| `service.rs` | 业务规则。这里禁止 `use axum` |
| `state.rs` | `RouterState`，里面是 service 和依赖，必须能 `Clone` |
| `error.rs` | 这个领域自己的错误 |

`state.rs` 的全部内容就是一个可克隆的结构体，Axum 每个请求都会克隆一份状态（克隆的是 `Arc`，不是把数据库拷一份）。

## 6. 进程启动，按 `main.rs` 往下读

`fn main` 很短：调用 `run_main()`，成功就用那个退出码，失败就 `error.report()` 再退出。

`run_main` 做四件事：

1. `Cli::parse()` 用 clap 解析参数。结构体在 `crates/aionui-app/src/cli.rs`。
2. 多数命令会调用 `aionui_runtime::init(&cli.data_dir)`，把托管运行时锚定到数据目录。短命的 MCP 子命令会跳过，避免去碰数据库。
3. `enhance_process_path()` 把常见的 Node、Agent CLI 路径补进 `PATH`。这行是 `unsafe`，因为 Rust 2024 里在运行时改环境变量被标成不安全，而且必须发生在任何工作线程出现之前。
4. 建 Tokio runtime，进入 `async_main`。

`async_main` 如果没有子命令（AionUi 拉起时就是这种）：

1. `bootstrap::init_environment` 准备配置、日志。
2. `DataDirInstanceGuard::try_acquire` 用文件锁占住数据目录。
3. `bind_http_listener` 绑端口。
4. `init_data_layer` 打开 SQLite 并跑迁移。
5. `AppServices::from_config` 把所有服务 new 出来。这是全项目唯一的组装点，领域 crate 不要自己 `new` 一整套依赖。
6. `commands::run_server` 开始接请求。同时监听父进程退出信号。

`AppServices` 在 `crates/aionui-app/src/services.rs`。你想知道「某个服务是谁创建的」，搜这个结构体字段，再看 `from_config`。

子命令（不启动长期服务器）包括：`doctor`（探测本机有哪些 Agent CLI）、`user`（改密码）、`secret`（加密密钥）、`capabilities`、各种给 Agent 调用的 `config` / `session` / `skills`。完整列表在 `cli.rs` 的 `enum Command`。

## 7. 一条 HTTP 请求怎么走

用「创建一个对话」做例子。

界面请求：

```http
POST /api/conversations
```

路由表在 `crates/aionui-conversation/src/routes.rs`：

```rust
.route("/api/conversations", post(create).get(list))
```

同一路径，POST 进 `create`，GET 进 `list`。

`create` 的签名就是项目约定的 handler 形状：

```rust
async fn create(
    State(state): State<ConversationRouterState>,
    Extension(user): Extension<CurrentUser>,
    body: Result<Json<CreateConversationRequest>, JsonRejection>,
) -> Result<(StatusCode, Json<ApiResponse<ConversationResponse>>), ApiError>
```

对照 TypeScript 的依赖注入：

| 提取器 | 含义 |
| --- | --- |
| `State(state)` | 路由状态，里面有 `ConversationService` |
| `Extension(user)` | 认证中间件塞进来的当前用户 |
| `Json(req)` | 把 body 反序列化成 `CreateConversationRequest` |
| `Path(id)` | URL 里的 `{id}` |
| `Query(query)` | `?` 后面的查询参数 |

handler 本身不做业务，只调用：

```rust
let conversation = state.service.create(&user.id, req).await.map_err(ApiError::from)?;
Ok((StatusCode::CREATED, Json(ApiResponse::ok(conversation))))
```

成功 JSON 形如 `{ "success": true, "data": { ... } }`。失败走 `ApiError`，形如 `{ "success": false, "error": "...", "code": "..." }`。类型定义在 `aionui-api-types`，不要在领域 crate 里再发明一套响应结构。

中间件顺序在 `routes.rs` 的 `create_router` 注释里：安全响应头 → CSRF → 具体路由。认证中间件由调用方套在需要登录的路由上。桌面 `--local` 会跳过真实登录，使用系统默认用户。

改一个接口的推荐顺序：

1. `aionui-api-types` 里改请求/响应结构
2. `aionui-db` 里改表或查询（如果要落库）
3. 领域 crate 的 `service.rs` 写规则
4. `routes.rs` 加一行 `.route(...)` 和薄 handler
5. `aionui-app` 里确认这个 `RouterState` 已经被 `build_module_states` 装上

路由前缀一律 `/api/`，资源名用 kebab-case，例如 `/api/ai-agents`。

## 8. 数据库

引擎是 SQLite，异步访问用 **sqlx**。连接池在 `crates/aionui-db/src/database.rs`：最多 5 个连接，busy timeout 5 秒。

表结构变更只能加新的 SQL 文件：

```text
crates/aionui-db/migrations/001_initial_schema.sql
...
crates/aionui-db/migrations/044_add_minimax_code_builtin_agent.sql
```

启动时 `sqlx::migrate!()` 会按顺序执行还没跑过的文件，并记在表 `_sqlx_migrations`。已经发布的迁移文件不能改内容。数据库比当前程序新（用户用旧二进制打开新库）会走专门的「需要升级」错误，而不是当成迁移损坏。

读数据的分层：

- `models/`：一行数据长什么样（`ConversationRow` 等）
- `repository/*.rs`：`IConversationRepository` 这种 trait
- `repository/sqlite_*.rs`：真正的 SQL

Service 的字段类型是 `Arc<dyn IConversationRepository>`，不是 `SqliteConversationRepository`。

## 9. WebSocket

HTTP 用来发命令和拉列表。Agent 一边生成一边吐字，走 WebSocket。

`create_router_with_runtime` 里会 `services.event_bus.subscribe()`，再 `tokio::spawn` 一个循环：事件里有 `user_id` 就推给该用户的连接，少数全局事件才广播给所有人，否则丢掉并打警告。

事件名约定是两段：`domain.camelCaseAction`。旧的 kebab-case 名字是历史遗留，新事件不要再模仿。

心跳间隔 30 秒、超时 60 秒，常量在 `aionui-common` 的 `constants.rs`。会话 Cookie 名是 `aionui-session`，CSRF Cookie 是 `aionui-csrf-token`，请求头是 `x-csrf-token`。

## 10. Agent 是怎么被拉起来的

AionCore 自己不实现 Claude / Codex 的对话逻辑。它按注册表找到本机 CLI，用子进程和协议沟通：

- 内置引擎来自 Git 依赖 `aion-agent`、`aion-providers` 等，仓库是 `iOfficeAI/aionrs`，tag `v0.2.11`（根 `Cargo.toml`）
- 外部 CLI 走 ACP（Agent Client Protocol）或各家直连协议
- 团队模式会再拉起一个 stdio MCP 服务（子命令 `mcp-team-stdio`）

`aioncore doctor` 会按和正式服务器相同的 PATH 去探测每个 Agent 是否可用。界面上「某个 Agent 不可用」，先在同一个环境跑 `doctor`，再看服务日志。

日志里不要打提示词、文件内容、令牌、模型原始请求。这是 `AGENTS.md` 的硬规则。

## 11. 读代码时的实用找法

| 你想知道 | 怎么找 |
| --- | --- |
| 某个 URL 谁处理 | 在 `crates` 里搜 `"/api/你的路径"` |
| 请求 JSON 有哪些字段 | `crates/aionui-api-types` |
| 业务规则 | 对应领域的 `service.rs`，不要停在 `routes.rs` |
| 谁 new 了这个服务 | `crates/aionui-app/src/services.rs` |
| 表在哪 | `crates/aionui-db/migrations` 和 `models/` |
| 命令行参数 | `crates/aionui-app/src/cli.rs` |
| 启动失败的错误码 | `main.rs` 里的 `MainError`，以及 `bootstrap/error.rs` |

编译报错时先看**第一条** `error`。后面几十行经常是连锁反应。`cannot find` 多半是 `lib.rs` 忘了 `mod` 或 `pub use`。`xxx doesn't implement Send` 是把不可跨线程的值丢进了 `tokio::spawn`。`mismatched types` 看期望类型和实际类型，经常只是缺了 `.await` 或 `?`。

`cargo check -p aionui-conversation` 可以只检查一个 crate，比重编整个 workspace 快。

## 12. 建议阅读顺序

按这个顺序打开文件，每一份只读下面写的范围，不要一上来通读 `service.rs`（对话服务很大）。

1. 根 `Cargo.toml` 的 `members` 和 `workspace.dependencies` 前 70 行，知道有哪些箱子、aionrs 从哪来。
2. `crates/aionui-app/src/main.rs` 的 `main`、`run_main`、`async_main`。
3. `crates/aionui-app/src/cli.rs` 的 `struct Cli` 和 `enum Command`。
4. `crates/aionui-common/src/error.rs` 的 `enum ApiError` 前 80 行。
5. `crates/aionui-common/src/constants.rs` 的端口、Cookie、心跳。
6. `crates/aionui-conversation/src/routes.rs` 的 `conversation_routes` 和 `create`。
7. `crates/aionui-conversation/src/state.rs` 全文（很短）。
8. `crates/aionui-db/src/repository/conversation.rs` 的 trait 前 40 行。
9. `crates/aionui-app/src/services.rs` 的 `struct AppServices`。
10. `crates/aionui-app/src/router/routes.rs` 的 `create_router_with_runtime` 前 190 行，看中间件和后台任务从哪来。

读完这 10 步，你就有一张地图。之后改哪个功能，就进对应 crate，仍然按 routes → service → repository 往下钻。

## 13. 词汇表

| 词 | 在这里的意思 |
| --- | --- |
| crate | 一个 Rust 包，对应 `crates/` 下的一个目录 |
| workspace | 多个 crate 共用一份依赖版本 |
| Tokio | 异步运行时，负责线程和 `.await` |
| Axum | HTTP 框架，负责路由和中间件 |
| handler | 处理一个 URL 的 async 函数 |
| extractor | `State`、`Json`、`Path` 这种「从请求里取出值」的类型 |
| trait | 接口 |
| `dyn Trait` | 指向某个实现了该接口的具体类型 |
| `Arc` | 多所有者共享，跨线程安全 |
| sqlx | 异步 SQL 库，迁移用它的 `migrate!` |
| ACP | Agent Client Protocol，和外部 Agent 通信的协议 |
| MCP | Model Context Protocol，给 Agent 挂工具 |
| aionrs | 内置 Agent 引擎，独立 Git 仓库，不在本目录源码里 |
