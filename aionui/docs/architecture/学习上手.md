# AionUi 学习上手

这份文档给第一次打开本仓库的人用。官方开发步骤在 [docs/contributing/development.md](../contributing/development.md)，目录规则在 [docs/contributing/file-structure.md](../contributing/file-structure.md)。这里讲「这个程序是怎么拼起来的，改功能该去哪看」。

版本以仓库当前 `package.json` 为准：AionUi `2.2.2`，配套后端 AionCore `v0.2.2`。

## 1. 它是什么

AionUi 是一个桌面应用（Electron），让你和多种 AI Agent 一起干活：读文件、写代码、做 PPT/Word/Excel、定时任务、手机远程访问。

它自己几乎不跑大模型。真正干活的是旁边那个 Rust 仓库 **AionCore**，编译出来的命令叫 `aioncore`。AionUi 启动时会自动拉起这个进程，再把界面画出来。

还有第三个仓库 **aionrs**（`https://github.com/iOfficeAI/aionrs`）。它是内置 Agent 引擎，被 AionCore 以 Git 依赖引进来，不在这两个仓库的源码里。

```text
你点的窗口（AionUi，TypeScript + React + Electron）
        │  HTTP + WebSocket
        ▼
本地后端 aioncore（AionCore，Rust）
        │  子进程 / ACP / MCP
        ▼
各种 Agent：内置 aionrs、Claude Code、Codex、Cursor Agent……
```

两个仓库要放在同一层目录：

```text
github/
├── AionCore/
└── AionUi/
```

## 2. 怎么跑起来

前置条件（来自官方开发文档）：

- Node.js 22 或更高，且低于 25
- bun（包管理器和脚本运行器）
- Rust stable + Cargo（用来编译 AionCore）
- Python 3.11+（编译原生模块时可能用到）

顺序不能反：先装好 `aioncore`，再启动界面。界面从 `PATH` 里找这个命令。

```bash
# 1. 编译并安装后端（在 AionCore 目录）
cd AionCore
cargo install --path crates/aionui-app --locked
export PATH="$HOME/.cargo/bin:$PATH"
which aioncore
aioncore --help
```

✓ 第 1 步完成标志：`which aioncore` 打印出路径，`aioncore --help` 能列出子命令。没有输出就是 `PATH` 里没有 `~/.cargo/bin`。

```bash
# 2. 装前端依赖并启动（在 AionUi 目录，且同一个终端能找到 aioncore）
cd ../AionUi
bun install
bun run start
```

✓ 第 2 步完成标志：Electron 窗口打开并进入首页，终端里没有 `Cannot find "aioncore" binary`。开发模式下它会自己启动 `aioncore`，你不用再开一个终端跑后端。

改了 AionCore 之后要重新安装二进制，再重启 AionUi：

```bash
cd AionCore
cargo install --path crates/aionui-app --locked --force
```

常用命令：

| 命令 | 作用 |
| --- | --- |
| `bun run start` | 开发模式桌面窗口 |
| `bun run webui` | 浏览器版，不开 Electron 窗口 |
| `bun run lint` | 检查代码（oxlint） |
| `bun run test` | 单元测试（vitest） |
| `bun run test:e2e` | 端到端测试（Playwright） |

启动失败时先在同一个终端执行 `which aioncore` 自查。

## 3. 仓库里你真正要看的目录

根目录的 `package.json` 是整个应用的脚本和依赖。真正的代码在 `packages/`。

| 目录 | 干什么 |
| --- | --- |
| `packages/desktop` | Electron 应用本体：窗口、界面、和系统打交道 |
| `packages/web-host` | 不依赖 Electron 的「宿主」：拉起 `aioncore`、提供 Web 静态服务 |
| `packages/web-cli` | 命令行启动 Web 版的入口 |
| `packages/shared-scripts` | 打包时准备 AionCore 资源的脚本 |
| `docs/contributing` | 贡献者规范 |
| `docs/guides` | WebUI、部署、主题等使用说明 |
| `docs/prds` | 产品需求稿 |
| `tests` | 单元测试和 E2E |

`packages/desktop/src` 分成三块，这是 Electron 的硬边界，混用会在运行时崩：

| 目录 | 能用什么 | 不能用什么 |
| --- | --- | --- |
| `process/` | Node.js、Electron 主进程 API | 网页 DOM、React |
| `renderer/` | React、浏览器 API | Node.js、Electron 主进程 API |
| `preload/` | 两边之间的桥 | 业务逻辑尽量不要堆在这里 |
| `common/` | 两边都能 import 的类型和适配器 | 直接访问磁盘或窗口 |

入口文件：

- 主进程：`packages/desktop/src/index.ts`
- 预加载：`packages/desktop/src/preload/`
- 界面：`packages/desktop/src/renderer/main.tsx`

路径别名（见 `packages/desktop/electron.vite.config.ts`）：

- `@` → `packages/desktop/src`
- `@process` → 主进程
- `@renderer` → 界面
- `@common` → 共享代码

## 4. 一次启动实际发生了什么

1. `index.ts` 先配置 Chromium、崩溃上报、单实例锁。第二个窗口会把链接交给已经打开的那个，然后自己退出。
2. `startBackendOrExit` 通过 `@aionui/web-host` 里的 `BackendLifecycleManager` 找到并启动 `aioncore`。
3. 启动参数在 `packages/web-host/src/backend-launcher.ts` 的 `buildSpawnArgs`：`--port`、`--data-dir`、`--parent-pid`、`--log-level`、`--app-version`，开发模式还会带 `--local`。
4. 端口由桌面端挑选（系统空闲端口），再传给后端。AionCore 自己单独运行时的默认端口是 `25808`（`aionui-common` 的 `DEFAULT_PORT`），被 AionUi 拉起时以传入的 `--port` 为准。
5. 后端健康检查通过后，主进程把端口交给界面（`window.__backendPort`），再创建窗口。
6. 父进程退出时，后端靠 `--parent-pid` 跟着退出，避免留下孤儿进程。

所以开发时「界面打不开 / 一直转圈」，先看终端里有没有 `Cannot find "aioncore" binary`，再看后端日志目录。

## 5. 界面怎么跟后端说话

界面不直接 `import` Rust。它发 HTTP，并维持一条 WebSocket 收实时事件。

HTTP 客户端在 `packages/desktop/src/renderer/api/client.ts`：`createApiClient(baseURL)` 提供 `get/post/put/patch/delete`。成功时解析 JSON，失败时抛 `ApiError`。

登录态在 `packages/desktop/src/renderer/hooks/context/AuthContext.tsx`，用 `fetch` 打认证接口。桌面开发模式后端带 `--local`，会走本地默认用户，少掉一套远程登录。

路由在 `packages/desktop/src/renderer/components/layout/Router.tsx`，用的是 Hash 路由（地址形如 `/#/guid`）。主要页面：

| 路径 | 页面 |
| --- | --- |
| `/guid` | 首页 / 引导 |
| `/conversation/:id` | 某个对话 |
| `/team/:id` | 团队模式 |
| `/assistants` | 助手 |
| `/settings/agent` | Agent 设置 |
| `/settings/skills` | 技能 |
| `/settings/tools` | 工具 |
| `/scheduled` | 定时任务 |
| `/login` | 登录（远程 / WebUI 会用到） |

界面技术栈（根 `package.json`）：React 19、Vite（electron-vite）、Arco Design、UnoCSS、CodeMirror / Monaco、i18next。新界面按项目规范优先用 Arco 组件和 `@icon-park/react` 图标。

## 6. 主进程里各文件夹干什么

`packages/desktop/src/process/`：

| 目录 | 干什么 |
| --- | --- |
| `startup/` | 后端启动、架构检查、退出清理、单实例 |
| `backend/` | 解析 `aioncore` 二进制在哪 |
| `bridge/` | 主进程和界面之间的 IPC 处理函数 |
| `services/` | 仍留在 Electron 侧的业务（例如部分系统设置、i18n） |
| `utils/` | 窗口大小、托盘、菜单、深链接、日志 |

跨进程规则：

- 主进程 ↔ 界面：走 `preload` + `process/bridge`
- 不要在 `renderer` 里 `import` Node 的 `fs`

大量业务（对话、文件、Agent、定时任务）已经在 AionCore。改「发一条消息之后后端做什么」，去 AionCore，不要在 AionUi 里找一个巨大的 Node 服务。

## 7. 和 AionCore 的分工（改代码时先判断）

| 你想改的东西 | 去哪 |
| --- | --- |
| 窗口、托盘、菜单、主题、按钮布局 | AionUi `packages/desktop/src/renderer` |
| 怎么启动后端、端口、健康检查 | AionUi `packages/web-host` |
| 对话、消息、权限确认、文件、定时任务、登录、数据库 | AionCore |
| 内置 Agent 怎么调模型 | aionrs（AionCore 的 Git 依赖，tag `v0.2.11`） |

AionUi 的 `package.json` 里有 `"aioncoreVersion": "v0.2.2"`，表示这版界面对应的后端版本。两边大版本对不上时，先对齐再查界面 bug。

## 8. 建议阅读顺序

1. 本文，建立两边关系。
2. `docs/contributing/development.md`，按命令跑起来。
3. `packages/desktop/src/index.ts` 只看启动段：单实例、`startBackendOrExit`、创建窗口。
4. `packages/web-host/src/backend-launcher.ts` 的 `buildSpawnArgs`。
5. `packages/desktop/src/renderer/main.tsx` 和 `components/layout/Router.tsx`，知道页面从哪进。
6. 打开 AionCore 的 `docs/学习上手.md`，顺着一条「创建对话」请求读到 Rust。

先把一条链路读通，再横向翻设置页、团队模式、定时任务。那些是同一套 HTTP + WebSocket 上的不同领域。

## 9. 在这台电脑上已经跑通的启动方式

> 本节是 2026-09 的本机实录，版本号会过时；真正长期有效的是里面的两个坑（`ELECTRON_RUN_AS_NODE` 和代理），它们在任何机器上都可能遇到。

当时的环境：bun 在 `~/.bun/bin`，Rust 工具链和 `aioncore` 在 `~/.cargo/bin`，开发数据目录是 `~/.aionui-dev`，后端库文件是里面的 `aionui-backend.db`。

从 Cursor 自带终端启动时，环境里会带 `ELECTRON_RUN_AS_NODE=1`。不关掉它，Electron 会当成普通 Node 跑，一启动就报 `electron.app` 是 `undefined`。用下面这段：

```bash
export PATH="$HOME/.cargo/bin:$HOME/.bun/bin:$PATH"
unset ELECTRON_RUN_AS_NODE
cd AionUi
bun run start
```

窗口起来后，界面会请求本机 `aioncore`。健康检查是 `GET /health`，正常返回 `{"status":"ok",...}`。开发模式带 `--local`，登录会被跳过，直接进首页。

下次改完 AionCore，先停掉这个窗口，再执行：

```bash
cd AionCore
cargo install --path crates/aionui-app --locked --force
```

然后重新 `bun run start`。正在跑的窗口不会自动换上新的后端二进制。

## 10. 动手一下（10 分钟）

光读记不住，动手改一处能立即看到效果的地方。任务：**把设置页的默认落地页从「Agent」改成「工具」**。

1. 打开 `packages/desktop/src/renderer/components/layout/Router.tsx`，找到 `<Route path='/settings' element={<Navigate to='/settings/agent' replace />} />`。
2. 把 `to='/settings/agent'` 改成 `to='/settings/tools'`，保存。
3. 在运行中的窗口里点设置入口。

✓ 完成标志：设置页打开后落在「工具」而不是「Agent」。Vite 热更新会立即生效，不用重启。观察完用 `git checkout -- <文件>` 还原。

这个任务让你亲手摸到第 5 节讲的路由文件，并验证「界面改动即时可见」的开发循环。

## 11. 词汇表

| 词 | 在这里的意思 |
| --- | --- |
| Electron | 桌面应用框架：一个 Chromium 窗口 + 一个 Node 主进程 |
| 主进程（main） | `packages/desktop/src/process/`，能用 Node 和系统 API |
| 渲染进程（renderer） | `packages/desktop/src/renderer/`，就是网页，只能写 React 和浏览器 API |
| preload | 两个进程之间的桥，决定界面能调用哪些主进程能力 |
| IPC | 主进程和界面之间的消息通道，走 `preload` + `process/bridge` |
| Hash 路由 | 地址形如 `/#/guid` 的前端路由，刷新不丢页面状态 |
| web-host | `packages/web-host`，不依赖 Electron 的宿主层，负责拉起后端 |
| aioncore | AionCore 编译出的后端命令，AionUi 启动时自动拉起 |
| aionrs | 内置 Agent 引擎，独立仓库，AionCore 以 Git 依赖引入 |
| ACP / MCP | Agent 通信协议 / 给 Agent 挂工具的协议，细节见 AionCore 文档 |

<details>
<summary>1. AionUi 启动时从哪里找到后端命令？</summary>

从 `PATH` 里找 `aioncore`。找不到就报 `Cannot find "aioncore" binary`。

</details>

<details>
<summary>2. 界面和后端之间走哪两种通道？分别干什么？</summary>

HTTP REST 发命令、拉数据；WebSocket 收 Agent 的实时流式事件。

</details>

<details>
<summary>3. 想改一个按钮的样式，应该动 `packages/` 下哪个目录？</summary>

`packages/desktop/src/renderer`。主进程目录 `process/` 里没有界面。

</details>

<details>
<summary>4. 为什么 `renderer/` 里不能 `import` Node 的 `fs`？</summary>

渲染进程是浏览器环境，没有 Node API，混用会在运行时直接崩。要读写文件得通过 preload + IPC 请主进程代劳。

</details>

<details>
<summary>5. 改了 AionCore 代码后，为什么要重新 `cargo install` 再重启 AionUi？</summary>

AionUi 拉起的是 `~/.cargo/bin` 里已安装的二进制，不重装就还是旧的；正在跑的窗口也不会自动换新，必须重启。

</details>

<details>
<summary>6. 界面路由用什么模式？地址长什么样？</summary>

Hash 路由，形如 `/#/conversation/123`，定义集中在 `Router.tsx`。

</details>
